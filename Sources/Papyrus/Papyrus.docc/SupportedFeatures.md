# 지원 범위와 성능

Papyrus가 지원하는 PDF 기능의 범위와, 대용량 문서를 다룰 때 기대할 수 있는
성능 특성을 정리합니다.

## 개요

Papyrus는 현재 버전 기준으로 암호화되지 않은 PDF의 구조 파싱·메타데이터·목차·
페이지 텍스트·검색·뷰어 표시·텍스트 선택·하이라이트에 표면을 집중합니다. 아래
목록은 현재 지원하는 항목과 의도적으로 다음 버전으로 미룬 항목을 정리한 것입니다.

**지원**

- xref 전 변형·증분 업데이트·손상 복구
- 메타데이터(Info+XMP)·목차·페이지 텍스트
- 검색과 하이라이트, 세로 스크롤과 줌 뷰어
- 텍스트 드래그 선택·복사(페이지 경계 포함)와 선택 메뉴 커스터마이징
- 개발자 정의 선택 가능 영역
- OCR 등 외부 텍스트 공급원 주입(`PageTextProvider`)
- 지속 하이라이트(`Codable` — 영속화는 앱 책임)
- 페이지 이미지 렌더링(`PageImageRenderer`)

**미지원 (현재 버전)**

- 암호화 문서 (감지 후 명시적 에러)
- 사전정의 CJK CMap (문자 위치는 유지, 대체 문자로 표시)
- 주석, 썸네일, 문서 전체 선택(⌘A), VoiceOver 텍스트 노출

암호화된 문서를 열려고 하면 `PapyrusError.encryptedDocument`가 던져집니다.
사전정의 CJK CMap이 없는 폰트로 인코딩된 텍스트는 글자 수와 위치가 정확히
유지되지만, 각 글리프는 대체 문자(U+FFFD)로 표시됩니다.

## 성능

아래 수치는 합성 픽스처를 Apple Silicon 기기에서 release 빌드로 로컬 측정한
설계 목표치입니다.

- 5,000페이지 문서 열기(`open` 후 `pageCount` 조회까지) 250ms 미만
- 이미 열린 문서에서 캐시된 `page(at:)` 호출 1ms 미만
- 매치가 없는 전체 문서 검색 스캔 200ms 미만

렌더링 타일 캐시의 예산은 `min(256MB, 기기 물리 메모리 / 8)`이며, 예산을 넘어서면
가장 오래 쓰이지 않은 항목부터(LRU) 축출됩니다. 시스템이 메모리 압박 신호를 보내면
캐시 예산이 절반으로 줄어들고(경고 단계), 압박이 심해지면 타일이 전량 비워집니다
(위험 단계).

선택 히트테스트 인덱스는 페이지·세션당 1회 구축되며 페이지 이탈 시 회수됩니다 —
문서 크기와 무관하게 상주 비용이 유계입니다.
